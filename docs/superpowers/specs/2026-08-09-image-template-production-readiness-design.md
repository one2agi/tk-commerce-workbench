# 生图模板生产可用性设计

## 目标

让桌面端 `/templates` 页面真正承担生图模板的创建、查看、编辑、提示词测试和启用工作，并确保启用后的模板可以被 Headless 生图链路使用。

## 已确认问题

- 页面将模板数据固定为 `[]`，数据库已有模板也始终显示为空。
- 创建、保存、启用或恢复后只调用 `router.refresh()`；因为服务端仍返回空数组，用户无法看到结果。
- 当前提示词测试接口绕过设置页保存的运行配置，在 `live` 模式下无法创建合法 Planner。
- 提示词测试只传入商品 ID，没有加载真实商品事实和参考素材，结果不能代表生产提示词。
- 类目标识是无说明的自由文本，容易出现无法匹配的测试值。
- 页面缺少主导航入口、页面标题、清晰空状态和足够的文字对比度。

## 方案选择

### 采用：服务端首屏数据 + 现有版本化接口

模板页面作为动态 Server Component，通过 `getServerServices().imageGenerationTemplates.list()` 获取首屏数据。客户端继续复用现有 POST、PATCH、activate、restore 接口；成功后刷新 Server Component，不额外引入 SWR、React Query 或新的客户端缓存。

这是当前项目最小、最稳定的修复：数据只有一个来源，创建和启用后即可看到数据库真实状态。

### 不采用：纯客户端加载

客户端 `useEffect` 拉取列表可以修复空页面，但会增加加载状态、竞态和双重数据源，同时首屏仍为空。现有页面已经使用服务端组合层，没必要增加依赖。

### 不采用：新建独立类目管理系统

当前业务没有独立类目字典，下游商品生图本来就是从“已启用模板”选择类目。为本次修复增加类目表、管理页和同步机制会扩大范围，也容易制造一套与真实商品不一致的假字典。

## 页面设计

页面保持单列桌面布局，不考虑手机端重新设计。

1. 顶部显示页面标题“生图模板”和一句用途说明。
2. 新建区保留“模板名称”和“类目标识”两个字段。
3. 类目标识提供：
   - 格式说明和示例，例如 `women.hat`。
   - 来自现有模板的 `datalist` 建议。
   - 前后端一致的格式校验，只允许稳定的英文、数字、点、短横线和下划线组合。
   - 重复类目标识的明确错误提示。
4. 空状态解释“尚未创建模板，创建并启用后才可开始 Headless 生图”，并将新建表单作为直接行动入口。
5. 模板列表优先显示已启用，其次草稿，最后归档；保留现有版本状态、摘要、高级设置、提示词测试和生命周期操作。
6. 左侧导航增加“生图模板”入口。
7. 页面提供独立 metadata；根文档语言改为 `zh-CN`，空状态颜色满足 WCAG AA。

## 数据流

### 列表与变更

1. 请求 `/templates`。
2. 服务端读取模板列表并传给 `ImageGenerationTemplateManager`。
3. 用户创建、保存、启用或恢复模板。
4. API 完成数据库写入。
5. 客户端执行 `router.refresh()`。
6. 服务端重新读取数据库，页面展示最新版本和状态。

任何接口失败时保留表单内容，显示具体、可操作的错误信息，不伪装成功。

### 提示词测试

1. 用户输入样例商品 ID，并选择要测试的模板版本。
2. API 通过 `ProductService` 加载商品工作区和真实 review facts。
3. API 从当前已应用的运行配置创建与 Worker 一致的 Planner，必须使用设置页保存的 Base URL、API Key 和模型。
4. Planner 接收真实商品事实和可用参考图片，只返回提示词，不创建批次、槽位或图片生成任务。
5. 页面展示生成出的提示词内容，而不只是显示数量。

如果运行配置不完整、商品不存在或 Planner 调用失败，返回安全错误码和中文操作提示。提示词测试不会调用图片模型，但可能产生 Planner 文本模型费用，界面需要明确说明。

## 运行配置边界

- Web 进程与 Worker 必须通过同一个运行配置加载入口取得已应用配置。
- 路由不得直接调用只读取环境变量的 `loadConfig()` 来绕过 UI 配置。
- live adapter 必须使用稳定的命令上下文；prompt test 的幂等键由模板、版本、商品和一次测试意图组成。
- API 响应和日志不得返回密钥。

## 测试与验收

### 自动化测试

- 页面渲染测试：服务端返回模板时，UI 必须显示模板而不是空状态。
- 创建测试：创建成功并刷新后，新模板可见。
- 类目标识测试：非法格式和重复值被拒绝，错误信息可操作。
- prompt-test 路由测试：使用注入的运行时 Planner、真实商品事实和参考素材；不创建生图任务。
- prompt-test live 配置测试：缺少已应用配置时返回明确错误，不退回 mock。
- 导航和 metadata 测试：模板入口、中文语言和页面标题存在。

### Chrome DevTools 验收

- 1440px 桌面视口，无水平溢出。
- 页面自行请求/服务端读取真实模板，UI 数量与 API 一致。
- 创建一个测试草稿后能够看到并编辑；不启用无效测试模板。
- 不实际触发付费图片生成。
- 控制台无 error/warning。
- Lighthouse Accessibility 不低于 95，Best Practices 保持 100。
- LCP 目标低于 1.5 秒，CLS 为 0。

## 非目标

- 不增加移动端专用布局。
- 不新建独立类目管理后台。
- 不重写模板版本模型或数据库表。
- 不在验收过程中调用付费图片生成模型。
- 不清理用户已有测试模板，避免未经授权删除数据。
