# 产品列表原图与洗图分区展示设计

## 目标

在 `http://127.0.0.1:3000/products/` 中直接展示每个商品采集到的全部原产品图，并与 Canvas 洗图后的图片分开展示。

用户不需要先进入商品详情页或展开下方内容，采集完成后即可在产品列表看到原图。点击图片只用于打开大图预览弹窗，不是查看原图的前置步骤。

## 用户可见效果

每个商品继续保留现有的标题、来源、价格、状态和批量操作能力。商品记录内新增两个独立图片区：

1. `原产品图`
   - 展示采集结果中的全部 `mainImages` 和 `detailImages`。
   - 主图在前、详情图在后，并按采集时的顺序排列。
   - 相同 URL 只展示一次。
   - 采集完成后立即出现在列表中。
2. `洗图后的图`
   - 展示 Canvas 生成的全部有效输出。
   - 生成结果到达后自动补充，不与原产品图混排。

两个图片区采用横向缩略图带。图片数量超过可用宽度时横向滚动，不增加整个商品记录的高度。这样可以容纳历史商品中几十张图片，同时保留产品池的批量管理效率。

## 大图预览弹窗

点击任意缩略图打开大图弹窗：

- 弹窗明确标记当前图片属于 `原产品图` 或 `洗图后的图`。
- 支持上一张、下一张切换。
- 支持键盘左右方向键切换，`Escape` 关闭。
- 显示当前位置，例如 `3 / 18`。
- 点击关闭按钮或遮罩可关闭弹窗。
- 关闭弹窗后，键盘焦点返回刚才点击的缩略图。

弹窗只浏览当前分区中的图片。浏览原产品图时不会跳入洗图结果，反之亦然。

## 数据设计

产品列表接口为每个商品返回两个明确字段：

- `originalImageUrls: string[]`
- `processedImageUrls: string[]`

原产品图来源于当前商品版本的 `source_payload.mainImages` 与 `source_payload.detailImages`。洗图后图片来源于当前版本的有效 Canvas 输出。

原产品图地址按以下优先级生成：

1. 已归档资产使用本地稳定地址 `/api/v1/assets/<assetId>/content`。
2. 尚未归档的图片使用受限的同源图片读取地址，由服务端获取允许的 1688/阿里图片域名。
3. 不把任意外部 URL 交给服务端读取，避免引入 SSRF 风险。

这样既能满足“采集后立即显示”，也能在图片归档完成后使用更稳定的本地副本。

## 组件边界

实现拆为三个职责清晰的部分：

1. 产品列表数据投影
   - 负责生成原产品图和洗图后图片两个有序数组。
   - 负责去重、过滤无效地址和选择本地归档地址。
2. 商品图片区
   - 负责两个分区的标题、数量、横向布局、加载状态和单图失败状态。
   - 不负责修改商品状态或业务流程。
3. 图片预览弹窗
   - 负责大图、前后切换、键盘操作、关闭和焦点恢复。
   - 接收单个分区的图片数组，不跨分区混合浏览。

## 加载与异常处理

- 图片使用懒加载，避免产品列表首次打开时同时请求全部历史图片。
- 单张图片加载失败时，该位置显示 `图片加载失败`，其他图片继续正常显示。
- 没有采集到原图时，原产品图区显示 `未采集到可用原图`。
- 尚未产生洗图结果时，洗图后图片区显示 `等待生成`。
- 无效或非 HTTP(S) 图片地址不进入接口结果。
- 受限同源读取地址只允许项目配置的 1688/阿里图片域名，并限制响应类型为图片。

## 测试与验收

### 自动化测试

- 服务层测试：
  - 合并主图和详情图，并保持顺序。
  - 去除重复和无效图片地址。
  - 已归档原图优先返回本地资产地址。
  - 原产品图与 Canvas 输出严格分开。
- 组件测试：
  - 两个图片区及图片数量正确渲染。
  - 采集原图无需展开或进入详情即可存在于 DOM。
  - 多张图片使用横向布局。
  - 点击缩略图打开正确分区的弹窗。
  - 上一张、下一张、方向键、`Escape` 和焦点恢复正常。
  - 单张加载失败不会隐藏其他图片。
- 接口测试：
  - 产品列表响应包含两个图片数组。
  - 外部图片读取仅允许指定域名和图片内容类型。

### 浏览器验收

使用真实的本地产品数据打开 `/products/`，确认：

1. 新采集商品不点击详情即可看到全部原产品图。
2. 已完成商品的原产品图与洗图后图片分区清晰，不再以洗图结果替代原图。
3. 图片较多时商品记录高度稳定，可横向浏览全部图片。
4. 点击图片可在弹窗中放大并连续切换。
5. 本地归档图片实际加载成功，页面没有遮挡批量操作区。

## 非目标

本次不改变采集流程、Canvas 生成逻辑、商品状态机、批量操作规则或商品详情页的信息架构。
