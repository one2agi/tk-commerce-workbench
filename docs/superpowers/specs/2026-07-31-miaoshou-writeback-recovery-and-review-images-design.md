# 商品详情洗图展示与妙手写回恢复设计

## 背景

商品 `prod_ms1tnmsvx2sxoh0r` 已成功生成 5 张 Canvas 洗图，并已由用户确认，但妙手采集箱 `3853105827` 仍保留原标题和 7 张 1688 原图。现有系统把这次结果显示成通用的“需要确认/结果未知”，没有明确告诉用户“写回未生效”，也没有安全的人工重试入口。

同时，商品详情页直接加载 Canvas 的远程 2048×2048 PNG，每张约 5–6MB，并把同一批图片在“最终图片”和“Canvas 输出”两个区域重复渲染。用户看到的是长时间空白，而不是系统没有洗图。

## 目标

本次改动解决四件事：

1. 商品详情页优先使用本地归档图片，并通过真实缩略图减少首屏下载量。
2. 保留妙手首次写回失败的安全错误证据，避免被后续核对结果覆盖。
3. 只有在远端核对明确证明 `no_change` 后，提供用户主动触发的安全重试。
4. 在详情页明确展示“妙手写回未生效 / 需要人工重试”及当前处理状态。

## 非目标

- 不自动重复调用妙手编辑接口。
- 不改变 Canvas 生成、图片审核或审批快照的业务规则。
- 不允许修改已批准的不可变审批快照。
- 不在界面或日志中暴露妙手响应原文、请求凭证、签名、Cookie 或完整请求体。
- 不把一般的“结果未知”错误都开放为可重试。
- 不修改产品列表页现有的原图/洗图区设计。

## 方案比较

### 方案 A：远端核对后人工重试（采用）

第一次写回结果不确定时，系统先读取妙手详情并进行核对。只有远端内容明确没有变化，详情页才展示“重新写回妙手”。用户点击后创建一个没有远端执行标记的新任务，继续使用原审批快照。

优点：

- 避免因网络超时但远端实际成功而重复写入。
- 用户能看到真实状态并掌握再次写入的时机。
- 保留审批内容，不需要重新洗图或重新确认。

代价：

- 用户需要多点击一次。
- 需要增加严格的服务端重试资格校验。

### 方案 B：核对无变化后自动重试一次（不采用）

优点是少一次操作，但外部系统状态和接口幂等能力不完全受本项目控制。自动重试会扩大外部写入风险，也让排查时难以区分用户动作和系统动作。

### 方案 C：只提示失败，不提供重试（不采用）

实现简单，但用户只能回到妙手手工处理，已经确认的洗图无法在工作台内恢复，业务闭环不完整。

## 用户可见设计

### 图片区域

商品详情页只把已经确定的最终图片展示为主要洗图结果：

- 图片地址使用本地 `/api/v1/assets/<assetId>/content`，不再直接依赖 Canvas 临时远程地址。
- 列表缩略图使用同一路由的受控缩略图模式，例如 `?variant=thumbnail`。
- 点击缩略图后，大图预览仍读取本地原始图片，保证清晰度。
- 如果某个 Canvas 输出已经出现在“最终图片”中，不在下方再次下载和渲染。
- 只有尚未进入最终图片顺序的 Canvas 输出，才显示在单独的“待确认 Canvas 输出”区域。
- 图片使用懒加载；单张图片失败不影响其他图片和写回操作。

缩略图固定在最长边 480 像素以内，保留原宽高比，自动旋转到正确方向并输出 WebP。缩略图响应设私有缓存，不覆盖原资产，也不改变写回妙手时使用的原图内容。

### 写回状态

详情页在确认按钮区域展示以下状态：

| 状态 | 用户文案 | 可执行操作 |
| --- | --- | --- |
| 未确认 | 尚未写回妙手 | 确认写回妙手 |
| 已排队/同步中 | 正在写回妙手 | 按钮禁用 |
| 成功 | 已写回妙手 | 无 |
| 核对后确认未变化 | 妙手写回未生效，远端仍为原内容 | 重新写回妙手 |
| 其他结果未知 | 妙手写回结果未知，需要人工核对 | 不开放重试 |
| 明确失败 | 妙手写回失败：安全错误说明 | 按现有流程处理 |

“重新写回妙手”有请求中的防重复点击状态。接口只返回稳定的业务错误码和安全文案，前端不自行判断是否具备重试资格。

## 数据与接口设计

### 详情页读模型

在 `ApprovalPreviewV1` 中增加 `miaoshouWriteback`：

```ts
type MiaoshouWritebackView = {
  state:
    | "not_started"
    | "queued"
    | "syncing"
    | "succeeded"
    | "failed"
    | "result_unknown";
  failureCode: string | null;
  safeMessage: string | null;
  retryAllowed: boolean;
  approvalSnapshotId: string | null;
};
```

服务端根据当前产品版本对应的最新审批快照、妙手同步记录和编辑任务生成该视图。前端只消费这个结论，不拼接数据库错误，也不依靠按钮文案推测状态。

### 重试接口

新增：

```text
POST /api/v1/products/<productId>/retry-miaoshou-edit
```

接口沿用本地回环访问和同源 CSRF 防护，成功时返回 `202 Accepted`。

事务内必须同时满足：

1. 产品当前版本仍与已批准快照一致。
2. 最新妙手同步状态是 `result_unknown`。
3. 最近一次远端核对结果明确为 `no_change`。
4. 对应编辑任务处于 `needs_input`，且存在原远端核对标记。
5. 当前没有排队或运行中的妙手编辑任务。

不满足任一条件时不创建任务，并返回稳定冲突码。符合条件时：

- 保留原审批快照不变。
- 创建一个新的 `miaoshou_edit` 任务，不复用旧任务的远端执行标记。
- 新任务使用带重试序号的唯一业务键，保证一次点击只创建一次。
- 把同步状态恢复为 `queued`。
- 写入人工重试审计事件，记录审批 ID、旧任务 ID、新任务 ID、重试序号和安全错误码。

## 失败证据设计

现有流程会先把第一次失败压缩为通用 `miaoshou.edit_result_unknown`，随后又用 `miaoshou_reconcile_no_change` 覆盖同步错误。调整后，`miaoshou_syncs.error` 保存结构化安全信息：

```ts
type MiaoshouSyncError = {
  kind: "reconcile_required";
  code: "miaoshou_reconcile_no_change";
  safeMessage: string;
  initialFailure: {
    kind: "network" | "timeout" | "remote_response" | "unknown";
    code: string;
    safeMessage: string;
  };
  reconciliation: {
    state: "no_change";
    checkedAt: string;
  };
};
```

适配器保留首次失败的安全 `code` 和 `safeMessage`。数据库仓储在保存核对结果时合并已有错误，而不是整体覆盖。审计日志只记录白名单字段，不记录响应正文和敏感请求信息。

历史失败证据在人工重试后仍通过审计事件保留；当前同步状态可以切回 `queued`，让详情页展示正在重试。

## 组件与代码边界

### Web

- 资产内容路由：解析 `variant=thumbnail`，用 `sharp` 生成受限尺寸 WebP；默认行为保持返回原文件。
- 产品服务：把最终资产 ID 投影成本地原图和缩略图地址，并计算写回状态视图。
- 最终图片区：最终图片只渲染一次；Canvas 区仅渲染未进入最终顺序的输出。
- 审批操作区：根据服务端视图展示状态、确认按钮或人工重试按钮。
- 重试 API：只负责权限边界、CSRF、调用事务服务和稳定响应映射。

### Worker / Adapter

- 妙手适配器：返回可安全持久化的首次错误分类，不再把所有不确定结果压成同一个码。
- 妙手编辑处理器：先保存首次失败证据，再执行远端核对；核对无变化时合并结果。
- 新重试任务继续走现有编辑处理器，不增加第二套写回实现。

### Database Repository

- 增加核对结果合并方法。
- 增加严格校验并创建人工重试任务的事务方法。
- 不新增数据库表或修改审批快照结构；错误历史用当前 JSON 字段和审计事件表达。

## 异常与并发

- 两次快速点击由事务锁和唯一业务键合并为一个新任务。
- 如果重试前产品版本已变化，返回 `409 revision_changed`，要求重新审核。
- 如果远端核对不是明确的 `no_change`，返回 `409 retry_not_allowed`。
- 如果已有任务正在排队或运行，返回 `409 writeback_in_progress`。
- 缩略图生成失败时返回明确错误，不回退代理外部远程地址；原图接口仍可独立使用。
- 不缓存错误响应，避免修复本地资产后继续看到失败占位。

## 测试策略

所有生产改动按测试驱动完成。

### 资产路由

- 默认请求继续返回原图和原内容类型。
- `variant=thumbnail` 返回最长边不超过 480 像素的 WebP。
- 非图片、不支持格式、越界资产和符号链接继续被拒绝。
- 缩略图和原图使用不同缓存头，错误响应不缓存。

### 服务与组件

- 详情页最终图片使用本地资产地址和缩略图地址。
- 同一资产不会在最终图片和 Canvas 输出中重复渲染。
- 五种写回状态对应正确文案和按钮。
- 只有 `retryAllowed=true` 才出现重试按钮。
- 重试请求期间不能重复提交，并正确显示成功和冲突错误。

### Adapter / Worker / Repository

- 网络、超时、远端响应错误保留各自安全错误码。
- 核对 `no_change` 后仍能读取首次失败证据。
- 非 `no_change`、版本变化、有运行中任务时拒绝重试。
- 合法重试创建新任务且没有旧远端执行标记。
- 并发重试只创建一个任务。
- 重试任务继续使用原审批快照中的 5 张已批准图片。

### 浏览器验收

使用商品 `prod_ms1tnmsvx2sxoh0r` 验证：

1. 详情页无需等待全部 2048×2048 原文件即可显示 5 张洗图缩略图。
2. 5 张洗图不会在两个区域重复出现。
3. 页面明确显示“妙手写回未生效，远端仍为原内容”。
4. 点击“重新写回妙手”只生成一个新任务，页面进入“正在写回妙手”。
5. 后续成功时显示“已写回妙手”；如果仍未生效，重新完成远端核对后再决定是否开放下一次人工重试。

## 上线与回退

该改动不含数据库迁移。旧记录默认仍按“结果未知，不允许重试”展示；但旧错误 JSON 的安全错误码已经明确等于 `miaoshou_reconcile_no_change`，且旧任务同时满足远端标记、`needs_input` 和 `reconcile_failed` 时，可作为兼容证据开放人工重试。其他旧版结果未知记录不开放重试。这样可以恢复本次已经核对过的采集箱 `3853105827`，又不会扩大重试范围。

如缩略图路径出现问题，可回退前端缩略图参数，原始本地资产路由不受影响。人工重试入口可通过服务端 `retryAllowed=false` 立即关闭，不影响已有同步任务。
