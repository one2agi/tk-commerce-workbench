# TK Commerce Workbench 产品定位与功能说明

日期：2026-07-23  
状态：当前产品准绳  
适用项目：`tk-commerce-workbench`

## 1. 一句话定位

TK Commerce Workbench 是一个面向 TikTok Shop 跨境运营的本地 AI 商品处理台。

它把 1688 商品从“采集成功”到“妙手公共采集箱待发布素材准备好”之间的重复工作自动串起来：采集、标题清洗、本地化、定价、Canvas `TK工作流` 生图、人工确认、写回妙手。

产品不是跨境 ERP，也不是单纯采集插件，更不是单纯 AI 生图工具。它是妙手前置的 AI 上架准备层。

## 2. 解决的核心痛点

跨境运营从 1688 找到一个商品，到能在 TikTok Shop 继续发布，中间通常要做大量重复动作：

- 复制链接、采集商品、整理 SKU 和图片；
- 下载、筛选、去水印、重做详情图；
- 改标题、翻译、本地化卖点；
- 计算目标站点售价；
- 上传图片和标题到 ERP；
- 等待处理结果，并手动判断下一步。

这些动作单独看都不复杂，但组合起来非常消耗运营时间，而且容易漏图、漏 SKU、算错价、写错标题、重复创建商品。

本产品要解决的是这段“上架前处理中间层”的低效问题。

## 3. 核心卖点：链路一键，而不是单点一键

竞品里常见的是单点一键：

- 一键采集；
- 一键翻译；
- 一键美图；
- 一键定价；
- 一键刊登。

但运营仍然要在多个模块之间来回切换、等待、检查、再点下一步。

本产品追求的是链路一键：

```text
浏览器勾选 1688 商品
→ 提交到本地工作台
→ 商品进入待处理
→ 用户点击开始处理
→ 系统自动完成采集详情、标题、定价、选图、Canvas 生图
→ 商品进入待确认
→ 用户确认写回妙手
→ 同一条妙手 canonical 公共采集箱商品被编辑
```

MVP 不追求无人值守发布，而是“自动处理，人工确认写回”。

## 4. 目标用户

首批目标用户是：

- 做 TikTok Shop 东南亚站点的跨境卖家；
- 从 1688 找货、测品、铺货或精铺的运营人员；
- 使用妙手 ERP 管理采集箱和后续发布流程的团队；
- 希望通过 AI 批量重构商品图文，但仍保留最终人工确认的卖家。

当前默认站点是泰国，默认语言方向是 `th-TH`，但语言不可写死，必须支持用户自定义目标语言和标题风格。

## 5. 产品原则

### 5.1 自动化优先

点击“开始处理”后，中间步骤默认自动推进，不给每个小环节都设计人工按钮。

自动处理包括：

- 下载并归档原始素材；
- 标准化商品、SKU、属性和单位；
- 清洗标题并生成目标语言 Listing；
- 自动计算目标站点售价；
- 自动过滤并排序 Canvas 输入图；
- 运行 Canvas `TK工作流`；
- 下载并归档 Canvas 输出；
- 生成最终待确认预览。

### 5.2 两道人为边界

MVP 只保留两个主动人工边界：

1. **开始处理**：费用边界。点击后才允许调用 LLM、汇率、Canvas 生图等可能产生费用的能力。
2. **确认写回妙手**：外部写入边界。点击后才允许编辑同一条妙手 canonical 公共采集箱商品。

异常情况下允许人工介入，例如缺配置、缺图、Canvas 失败、妙手结果未知、1688 登录失效。

### 5.3 不替代妙手

妙手是 ERP 和待发布池。  
本产品是妙手前置处理台。

MVP 的终点是妙手公共采集箱 / 待发布后续流程，不自动认领到 TikTok 采集箱，不自动发布 TikTok 商品。

### 5.4 不做大而全 ERP

MVP 不做订单、库存、仓储、物流、客服、广告、财务、多店铺权限、多租户计费。

这些是妙手、店小秘、芒果店长、马帮、通途等 ERP 的主战场，不是本产品当前主战场。

### 5.5 Canvas 工作流是差异化能力

本产品不只是“去水印”或“换背景”。

Canvas `TK工作流` 的目标是基于商品图生成结构化电商素材，例如：

- 主图；
- 卖点证明图；
- 场景价值图；
- 细节结构图；
- 人群 / 信任收尾图。

Canvas 内部可以继续迭代模型、提示词和节点。本产品只负责选择合适输入图、触发工作流、跟踪状态、归档输出和展示结果。

## 6. MVP 功能范围

### 6.1 浏览器扩展采集

- 支持在 1688 商品列表或店铺页面扫描商品卡片；
- 用户只提交勾选商品；
- 支持批量选择；
- 扩展本身保持轻量，不直接调用 Canvas 或妙手写入接口；
- 扩展通过本地 Bearer Token 向工作台提交采集请求。

### 6.2 妙手采集与详情导入

- 本地平台调用妙手 `fetch_item` 采集 1688 商品；
- 通过 `sourceItemIdAndDetailIdMap` 找到成功的公共采集箱详情；
- 查询并导入妙手标准化商品详情；
- 按 canonical source URL / source product ID 去重；
- 写回时编辑同一条 canonical 妙手公共采集箱商品，避免重复创建。

### 6.3 商品处理台

商品处理台是运营主入口，负责展示：

- 商品图片；
- 标题；
- 来源；
- 采集时间；
- 业务状态；
- 图片进度；
- 问题提示；
- 下一步动作。

主要状态：

| 状态 | 用户含义 | 主动作 |
| --- | --- | --- |
| 待处理 | 商品已进入工作台，还未消耗模型或生图费用 | 开始处理 |
| 自动处理中 | 系统正在采集详情、归档图片、清洗标题、定价、选图或生图 | 显示进度 |
| 待确认 | 标题、价格、图片和检查结果已准备好 | 查看并确认 |
| 写回妙手中 | 用户已确认，系统正在编辑妙手商品 | 显示进度 |
| 已完成 | 已写回妙手公共采集箱 | 查看记录 |
| 需要人工处理 | 缺少信息、外部结果未知或某环节失败 | 查看原因 / 重试 |

### 6.4 自动标题与 Listing 处理

- 清理 1688 供应商噪音；
- 保留商品事实、材质、规格、可见卖点；
- 生成目标语言标题；
- 支持用户自定义语言和标题风格；
- 标记风险词、极限词、虚假承诺和不可确认卖点。

标题和 Listing 数据治理属于本产品，不完全依赖 Canvas LLM。

### 6.5 自动定价

- 支持按公式计算售价；
- 支持汇率、利润率、平台费、运费、溢价等参数；
- 定价结果进入待确认预览；
- 缺少关键成本时进入“需要人工处理”，不使用猜测价格继续写回。

### 6.6 Canvas `TK工作流` 生图

- 使用 Canvas `TK` 画布中的 `TK工作流`；
- 预期输出 5 张电商图；
- 输入图片数量按实时工作流容量校验；
- 不为了填满槽位重复传图；
- Canvas 输出必须回到本地商品详情页可预览；
- 成功输出需要归档，避免只依赖临时 URL。

### 6.7 商品详情 / 图片确认页

详情页承载最终运营复核：

- 原始图片；
- Canvas 生成图；
- 标题和本地化 Listing；
- SKU / 属性 / 价格；
- 检查结果；
- 失败原因；
- “确认写回妙手”主动作。

商品列表不承载复杂编辑，只承载筛选、状态判断和批量操作。

### 6.8 写回记录

- 展示每次确认写回的商品、时间、状态、canonical 妙手详情 ID；
- 区分“已采集到妙手”和“已编辑回妙手”；
- 写回失败时提供可读原因和重试入口。

### 6.9 设置与诊断

设置页只放真实影响运行的配置：

- 妙手连接；
- Canvas 地址、画布和工作流；
- LLM 配置；
- 汇率服务；
- 定价公式；
- 默认目标语言和标题风格；
- 本地扩展 Token。

任务中心不作为主导航入口，降级为“设置 → 系统诊断 / 任务日志”，用于排查后台任务，不作为运营主入口。

## 7. 明确不做的事情

MVP 不做：

- 自动发布 TikTok；
- 自动认领到 TikTok / Shopee / Ozon 平台采集箱；
- 绕过最终人工确认直接写回妙手；
- 全店无确认自动采集；
- 多租户、账号登录、权限、团队协作；
- 仓储、物流、订单、客服、广告、财务；
- 本地维护复杂类目属性库；
- 本地维护 Canvas 参考图和生图风格库；
- 用 Excel 作为事实来源；
- 把妙手当作唯一数据源。

## 8. 与竞品的区别

### 8.1 相对妙手 / 店小秘 / 芒果店长

这些 ERP 功能全面，覆盖采集、刊登、订单、库存、物流、采购、广告和财务。

本产品不和它们正面对打 ERP 大而全能力，而是聚焦它们前面的 AI 上架准备层：

```text
1688 商品
→ AI 图文处理台
→ 妙手公共采集箱
→ 后续由妙手继续认领 / 发布 / 管理
```

差异不是“我们功能更多”，而是“我们把一个具体运营链路串得更少点击、更顺”。

### 8.2 相对 Photoroom / Pebblely / Flair / Claid 等 AI 商品图工具

这些工具强在图片质量、背景、光影、批量图片处理。

本产品强在业务链路：

- 懂 1688 商品采集；
- 懂妙手公共采集箱；
- 懂商品处理状态；
- 懂标题、定价、图片和写回之间的顺序；
- 能把 Canvas 工作流嵌入到上架准备流程里。

AI 商品图工具通常停在“生成图片”，本产品要走到“确认后写回妙手”。

## 9. 成功标准

MVP 成功不以“功能很多”为标准，而以一条真实链路是否顺畅为标准：

```text
1688 勾选商品
→ 提交到本地工作台
→ 商品进入待处理
→ 点击开始处理
→ 自动生成标题、价格和 5 张 Canvas 图
→ 商品进入待确认
→ 用户确认写回妙手
→ 同一条 canonical 妙手公共采集箱商品被编辑成功
```

用户视角的成功标准：

- 知道商品现在在哪一步；
- 知道下一步该点什么；
- 不需要手动串联多个工具；
- 失败时知道原因和恢复动作；
- 最终能在妙手继续后续发布流程。

技术视角的成功标准：

- 采集、处理、生图、写回都有持久状态；
- 任务失败可重试、可诊断；
- Canvas 使用 `TK工作流` 并返回可预览输出；
- 妙手写回作用于 canonical 商品；
- 不因重复点击产生重复费用或重复商品。

## 10. 当前产品表述

推荐对外 / 对内统一使用：

> TK Commerce Workbench 是一个面向 TikTok Shop 跨境运营的 AI 商品处理台。它把 1688 商品采集进来，自动完成标题、本地化、定价和 Canvas 详情图生成，人工确认后写回妙手公共采集箱。核心价值是把跨境上品从多步工具操作，压缩成一次采集、一次处理、一次确认。
